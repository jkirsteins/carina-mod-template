Copying an example ​

This page is a checklist for starting a mod from one of the example mods. Each line gives the reason.

The template holds the examples under mods/. Copy the folder, then change each item below.

  1. Id. Set a new id in mod.json. Two mods with one id are the same mod to the game, and saves and dependencies name a mod by its id.
  2. Record keys. The examples use the namespace carina_team.<slug>, with - read as _. Replace it with yours in every record key and every reference to a key: records, patches, assets/roles.json (races and artFrom) and migrations. A key outside your namespace is refused.
  3. Text keys. They hold the namespace too, for example wpn.carina_team.prism_optics.prism_beam.name. Rename them in the text files and in every nameKey and descKey that names them.
  4. Role names. An added race has role names that hold its key, such as races.portrait.select.<race key>. A building's lot role is colony.lot.<building key with _ written as ->. Rename both with the keys.
  5. Dependencies. Check the ids and ranges in dependencies, and loadAfter. Drop the ones your copy does not need.
  6. Version. Set version and rulesVersion back to their starting values, and delete the original's migrations/ folder.
  7. Display fields. Set title, summary and authors.
  8. Licence. The examples are CC-BY-4.0. Set license. If you keep files of the example, list them in sources with the example's author and licence, and put the example's packageHash in basedOn. CC-BY-4.0 requires credit.
  9. Check it. Run npx carina-modkit vscode so the editor knows the new folder, then npx carina-modkit check mods/<your mod>.

Walk the issues check prints. The first stage that fails stops the rest, so run it again after each fix.
