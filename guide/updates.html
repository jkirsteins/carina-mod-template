Releasing an update ​

This page covers versions, hashes, and what an update does to saves made with an earlier version.

Version and hashes ​

version is a semver number that names the release. Raise it with every release.

check and pack print three hashes. The game uses them to decide whether a save fits a mod.

HashCovers
rulesHashThe rules files (records, patches, migrations) and the manifest fields id, format, rulesVersion, phase, dependencies and loadAfter.
presentationHashText, pictures, sound and the preview, and the display fields of the manifest: title, summary, authors, license, sources and the others.
packageHashThe whole normalised manifest, with version, and both hashes above. It does not depend on the zip bytes.

version enters packageHash only. The sha256 that pack prints is of the .carinamod file, and the catalog lists it. Another Node.js version may compress differently and give another sha256. The packageHash does not change.

A save keeps one lock entry per mod: id, version, rulesVersion, rulesHash and packageHash.

What an update does to old saves ​

ChangeOld saves
Text, pictures or soundThey load. rulesHash is unchanged.
Rules, same rulesVersionThey load only where the old version is still installed. Elsewhere they are refused with modMismatch.
Rules, higher rulesVersion, with a migration for every stepThey load with the new rules.
Rules, higher rulesVersion, without the migrationThey are refused with missingModMigration.

A save takes the installed package with the exact packageHash first. If there is none, it takes the copy the share file carries, and then the newest installed version. That is why a rules change at the same rulesVersion works for a player who still has the old version.

A save made with a higher rulesVersion than the one running is refused with newerMod.

Migrations ​

To make old saves load with new rules:

  1. Raise rulesVersion in mod.json by one.
  2. Add migrations/<old>-<new>.json, for example migrations/1-2.json.
  3. Release with a higher version.

A later release adds the next step file. The files form a chain with no gap, and the chain need not start at 1. The last to is at most rulesVersion.

A migration file holds exactly $schema, from, to, renames and removals. from and to equal the numbers in the file name, and to is from plus one. Both lists are required and may be empty. Use empty lists when no key changed.

Renames ​

A rename moves a saved record to a new key of the same catalog. Pulse Lance 1.1.0 renamed the keys pulse_cannon to pulse_lance:

json
{
  "$schema": "carina-mod-migration/1",
  "from": 1,
  "to": 2,
  "renames": [
    {
      "catalog": "applications",
      "from": "carina_team.pulse_lance.pulse_cannon",
      "to": "carina_team.pulse_lance.pulse_lance"
    },
    {
      "catalog": "weapons",
      "from": "carina_team.pulse_lance.pulse_cannon",
      "to": "carina_team.pulse_lance.pulse_lance"
    }
  ],
  "removals": []
}

Removals ​

A record you removed needs a removal. It names a replacement key, or a reason to refuse. A refuse removal refuses the load only when the saved state still refers to that record.

json
{
  "$schema": "carina-mod-migration/1",
  "from": 2,
  "to": 3,
  "renames": [],
  "removals": [
    {
      "catalog": "weapons",
      "key": "carina_team.pulse_lance.pulse_lance",
      "replacement": "carina_team.pulse_lance.pulse_beam"
    },
    {
      "catalog": "buildings",
      "key": "carina_team.pulse_lance.pulse_works",
      "refuse": "Pulse Works no longer exists. Finish the game with version 1.1.0."
    }
  ]
}

Rules ​

  • Keys are the package's own: the namespace, then [a-z][a-z0-9_]*. The catalogs are open catalogs.
  • A refuse reason is 1 to 200 characters.
  • A target key that the new version does not define makes the load fail with modIncompatible.
  • The old id stays reserved in the save's id map.
  • Any fault in a file is reported as bad-mod-migration.

Pulse Lance is a complete example. Its tests load a save made with 1.0.0 into 1.1.0.

Testing an old save ​

  1. Keep the old .carinamod.
  2. Import it, start a game with it, and save.
  3. REMOVE the mod on the INSTALLED tab. The game asks Remove the mod? and warns Saves may need it. Press REMOVE.
  4. Import the new .carinamod.
  5. LOAD the save.

The Load dialog lists the save's mods. A mod installed in another version shows You have <version>. PLAY loads the game. The game then loads or refuses the save as the table above says.
