Testing ​

This page covers the loop of checking a mod, playing it with computer players, importing it and testing it in the game.

The loop ​

  1. Edit files. An editor with the JSON Schemas flags mistakes as you type. npx carina-modkit vscode writes the schemas and the VS Code settings for every mod folder.
  2. npx carina-modkit check mods/<mod> runs the game's own checks.
  3. npx carina-modkit run mods/<mod> --turns 50 plays computer players under your rules.
  4. npx carina-modkit pack mods/<mod> writes the .carinamod.
  5. Import it in the game, or use dev mode.

check ​

check prints what the game would say on import. Every issue names the severity, a code, the mod and file, the JSON path in the file and what was expected. check stops at the first stage that fails, so fixing one issue can show the next.

  • --json prints the report as JSON.
  • --with <folder> adds a mod that yours needs, when it is not in a sibling folder. See Dependencies and compatibility.

The Check my mod page runs the same importer in the browser. It checks one mod at a time against the built-in rules.

run ​

run plays computer players under your rules and prints the ruleset hash, a digest of the final state and one line per application, building, weapon or race the mod adds, with how many empires, colonies or designs use it. A line with a count of 0 means the computer players never used it.

  • --turns N sets the number of turns. The default is 50.
  • --seed N sets the game seed. The default is 1.
  • --players N sets the number of empires, 2 to 8. The default is 4.
  • --json prints the result as JSON.

A broken game invariant makes run fail with the invariant named.

pack ​

pack writes dist/<id>-<version>.carinamod in the working folder and prints its sha256 and the three hashes. --out <dir> writes to another folder. Releasing an update explains the hashes.

Importing into the game ​

  1. Open MODS on the main menu. The INSTALLED tab lists the mods on your device.
  2. Press IMPORT and pick the .carinamod file. In a desktop browser, drop the file or the mod folder on the screen instead.
  3. Select the mod. The details box shows what it holds, what it adds and changes, and any issues, the same list check prints.
  4. For a rules mod, open New Game, press RULES, switch the mod on and press ACCEPT. The picker shows the order the mods compose in and lets you pick a winner when two mods change the same value.
  5. A cosmetic pack is switched on or off with the ON/OFF switch in its row on the INSTALLED tab instead.

Dev mode ​

Dev mode reads a mod folder directly, so a change needs no packing.

  1. Open MODS, then DEV MODE. Or add ?moddev to the end of the game's address.
  2. Press FOLDER and pick mods/<mod>. Chrome and Edge read the folder again within a second of each save. Firefox and Safari cannot watch a folder: press FOLDER again after editing.

The game reads the folder, compiles it and lists the issues.

The status line says what a change needs:

  • Rules changed: RESTART or LOAD to play them.
  • Only text or art changed: no restart needed.

The buttons:

  • RESTART starts your last new game again, with the same setup and seed, under your rules. Without an earlier game it opens New Game.
  • LOAD opens the Load dialog. A game saved with the mod as it is now loads with it. After a rules change such a save no longer matches, so use RESTART.
  • COPY copies the issues as text.
  • POLICY shows the content policy.

New Game keeps using the mod's rules until the page is reloaded.
