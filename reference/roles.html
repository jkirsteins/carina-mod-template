Roles: pictures and sound ​

A role is a place in the game that draws a picture or plays a sound. assets/roles.json connects your files to roles: { "role": "<role id>", "file": "assets/<path>" }. A picture is a PNG (or WebP) of the exact size in the table; a file of the wrong size or kind is refused when imported, with the role named. Atlases that bring frames are the exception (see below). This page lists every role the base game draws, so every role a package can replace; the numbers in the last column count the roles one row stands for.

Placeholders in a role id: <race> is a race key (the 13 stock races, or a race your package adds), <banner> one of the eight banner colours (red, yellow, green, silver, blue, brown, purple, orange), <n> a number. A pair such as {a, b} lists the last segment of several roles in one row.

Besides the roles below, a package may add a new picture role <your namespace>.<name> (any size), and its own building and race roles as described in the sections for them. Sound is Ogg (Opus or Vorbis). An optional .m4a twin has the same role with .m4a added.

Combat ship atlas frames ​

A combat atlas holds one trimmed sprite per unit key, heading and frame, named <key>.h<0-4>.f<0-3>.x<X>.y<Y> (^([a-z0-9-]+)\.h([0-4])\.f([0-3])\.x(\d{1,2})\.y(\d{1,2})$): h the heading (five drawn headings, mirrored to sixteen facings), f the frame (frame 0 is required, the glow frames 1 to 3 are optional), X and Y the sprite's offset in its cell. Each rect must lie inside the image; every key and heading of the role must be present. The unit keys are 0 to 7 for ships.combat.<banner>.<hull> (hulls frigate, destroyer, cruiser, battleship, titan, colossus), colony, outpost, transport for ships.combat.<banner>.support, and for shipsai.combat.<race or group>.<hull> one sprite per banner colour (red, yellow, green, silver, blue, brown, purple, orange), or one sprite keyed by the group name for amoeba, crystal, dragon, eel, guardian, hydra, vaelori. The frames are listed in roles.json: "frames": [{ "name": "...", "x": 0, "y": 0, "w": 40, "h": 40 }].

Music and effects ​

Music is at most 300 seconds long, an effect at most 10; each role is an .ogg file with an optional .m4a twin. A race that names no art base also supplies its theme as music.race.<race key> (the twin is required there); the stock races' themes are music.cue.101 and up, in race order. The rows list the roles of the base.

Building lot art ​

A building a package adds is drawn on the colony lot from the atlas role colony.lot.<building key, with each _ written as ->. The record key of a building is <namespace>.<name> with underscores, for example carina_team.prism_optics.prism_lattice, so its role is colony.lot.carina-team.prism-optics.prism-lattice. A building with no lot art draws nothing on the lot; artFrom instead draws it as a base building (a building has either one, never both). The base has 49 lot roles, one per building, named the same way from the base building keys; a package replaces one by supplying that role.

The atlas holds 36 trimmed sprites, one per cell of the 6 x 6 lot, named r<0-5>c<0-5>_x<X>_y<Y> (^r([0-5])c([0-5])_x(-?\d+)_y(-?\d+)$): r the row, c the column, X and Y the screen position of the sprite's top-left pixel (they may be negative at the left edge), and the frame rect x, y, w, h the sprite's place in the image. Every cell appears once; rects lie inside the image and do not overlap; the sprite's screen rect X, Y, w, h lies inside the box of its cell (the table).

Worked example: Prism Optics ​

mods/prism-optics/ adds the building carina_team.prism_optics.prism_lattice. Its assets/roles.json has one row for the lot atlas, colony.lot.carina-team.prism-optics.prism-lattice, with the file assets/lot/prism-lattice.png (1024x369) and 36 frames, one per cell:

json
{
  "role": "colony.lot.carina-team.prism-optics.prism-lattice",
  "file": "assets/lot/prism-lattice.png",
  "frames": [
    { "name": "r0c0_x236_y361", "x": 0, "y": 0, "w": 160, "h": 127 },
    { "name": "r0c1_x162_y340", "x": 162, "y": 0, "w": 145, "h": 117 },
    ...
  ]
}
  • r0c0_x236_y361: the sprite of row 0, column 0, drawn with its top-left pixel at screen position (236, 361); it is 160x127 pixels at 0, 0 in the image.
  • r0c1_x162_y340: the sprite of row 0, column 1, drawn with its top-left pixel at screen position (162, 340); it is 145x117 pixels at 162, 0 in the image.
